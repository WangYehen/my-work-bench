> 文档版本：v1.0（草案）

> 范围对象：Personal AI Workbench（person_dashboard/Workbench）

## 1. 背景与目标

### 1.1 背景

Personal AI Workbench 是一个本地优先、Vault 驱动的个人知识与工作管理台，已具备知识库、阅读、图谱、任务、周重点、会议、日报、Outlook、钉钉、社媒洞察等十余个模块。功能覆盖面广，但存在三个突出问题：

1. **缺少产品主线**：十几项功能呈"功能陈列"状态，用户不知道每天应该从哪里开始、按什么路径做事，"不知道从哪入手"是当前最大痛点。
2. **工作数据割裂**：任务在本地 SQLite、邮件在 Outlook、日程在钉钉、日报在 Team Server/Electron 本地，聚合和闭环依赖页面各自拼装，缺乏统一的工作流叙事。
3. **团队协作侧薄弱**：日报从"个人自动生成"到"团队管理视图"链路存在，但缺少提醒、催办、表扬反馈循环和可量化的团队健康度指标。

### 1.2 目标（本 PRD 范围）

以"**每天从 Today 出发，用一条主线把任务关掉、把成果交出去**"为产品叙事，聚焦两个能力域：

- **工作管理闭环**：个人从"捕获 → 计划 → 执行 → 复盘（周报）"的完整回路。
- **日报与团队协作**：个人日报 → 主管汇总 → 团队洞察与反馈的协作价值链。

### 1.3 非目标

- 不重构知识库/阅读器/图谱（保持现状可用）。
- 不做移动端原生应用（保留响应式适配）。
- 不抓取平台数据以外的新数据源（Douyin/Social 维持"读 Vault 已整理数据"策略）。
- 本 PRD 的里程碑拆解服务于"先做什么"的决策，不承诺一次全部落地。

### 2.2 数据流转现状（四大存储）

```text
【内容事实源】个人知识库 Vault (Markdown/CSV/JSON)
        │  scan/index (server/vault-index.mjs)
        ▼
【本地应用状态】SQLite (.local/workbench.sqlite)
    ├─ tasks 任务        ├─ weekly_focus 周重点
    ├─ reader_notes      ├─ reader_explanations
    └─ material_reading_queue
        │
        ▼  /api/* (vite-plugin-workbench.mjs, Vite 内置 API)
【React 前端】页面各自拉取聚合 → Today/周报/日报
        ▲
        │  HTTPS (Bearer Token) / Electron IPC
【团队数据】Team Server (MySQL) :8787
    ├─ users(钉钉身份/汇报关系)  ├─ daily_reports(按人按日唯一)
    ├─ dingtalk_tokens(加密)     └─ audit_logs(审计)
【桌面离线】Electron 本地日报草稿 → 登录后同步到 Team Server
```

### 2.3 关键现状结论（问题清单）

1. **Today 页是全仓最强的聚合入口，但"行动"缺少统一来源标记**：任务(本地)、邮件(Outlook)、目标(周重点)三源混排，无法区分来源、无法一键回源。
2. **任务只有"完成/删除"，缺少生命周期**（无状态流转、无截止提醒、无逾期治理、无任务分派给他人）。
3. **周重点的进度是手工滑杆**，与任务完成数没有自动联动。
4. **日报提交后对个人是"黑盒"**：无已读/反馈状态；主管侧"标记已决策"不回流给提交人。
5. **催办与提醒缺失**：无未提交提醒、无主管催办通道、无提交率趋势。
6. **角色模型仅两级（管理员/普通成员）**，无"直属主管"的中间视图（dashboard 已含 reportRecipient 字段但前端未消费汇报链）。
7. **周报导出是本地 Markdown 文件**，未进入团队可见范围，团队周报由管理员侧单独汇总（weekly-summary），两条周报叙事未打通。
8. **日报素材收集依赖当天"已完成任务+会议+邮件"**，若用户关掉页面或未同步，素材会缺失。

## 3. 目标用户与核心场景

### 3.1 用户角色

| 角色 | 定义 | 核心诉求 |
| --- | --- | --- |
| 普通成员 | 每天提交日报、执行任务 | 不超过 2 分钟完成日报；清楚今天做什么；知道日报被看见的反馈 |
| 直属主管 | 直接上级，收下属日报 | 5 分钟扫完全组日报；一眼看到阻塞与风险；能催办和表扬 |
| 团队管理员 | 全局视图（当前已有） | 提交率、阻塞面、决策留痕、周度复盘 |

### 3.2 核心场景（用户故事）

- **US-01 早晨开局**：成员打开工作台首屏（Today），一眼看到"今天必须完成的任务、即将到期的邮件行动、本周目标进度"，不思考即可开工。
- **US-02 下午收口**：成员在 Today 勾选完成任务，完成即进入当天日报素材。
- **US-03 日报提交**：成员一键生成日报草稿，编辑后提交；提交后能看到"已送达直管"状态；次日上班前如未提交，收到工作台内提醒。
- **US-04 主管巡组**：主管打开团队日报页，按部门/日期看到提交率与未提交名单，一键催办（在应用内提醒对方的日报页），逐条处理"阻塞"并标记决策；决策结果回流给提交人。
- **US-05 周五复盘**：主管生成团队周报（由一周日报聚合而来），成员侧周报也引用团队周报结论，两个视角对齐。

## 4. 产品叙事：一条主线

> 主线（TODAY → CLOSE THE LOOP）：
> **今日行动（Today） → 执行与完成（任务/邮件） → 日报交付（提交与送达） → 主管反馈（决策回流） → 周度复盘（个人+团队周报） → 回到计划（下周重点）**

所有迭代功能必须回答"在主线哪一环、让用户少做什么"。

## 6. 详细需求（P0 细化）

### 6.1 A-1 Today 行动卡片升级

**用户故事**：作为成员，我想在 Today 页分清每个行动的来源和紧急程度，这样我不用切页就能判断先做什么。

- 行动卡片新增字段展示：
  - 来源徽标：`本地任务`（灰）/ `Outlook 邮件`（蓝）/ `周目标`（紫）。
  - 截止时间（有则显示）；逾期时红字"已逾期 N 天"。
- 点击本地任务行动 → 跳转 `/todos?highlight=id`；邮件行动 → `/outlook`（定位回源）；目标行动 → `/weekly-focus`。
- 分组顺序：已逾期 → 今天截止 → 高优先级 → 稍后（保持现状语义，仅增强贴标）。
- 勾选完成的动作路径不变：完成本地任务调 `PATCH /api/tasks/:id`；邮件行动继续现状（转待办后再完成）。

**验收标准**：
- [ ] Today 页每个行动可辨识来源与逾期状态；
- [ ] 点击行动跳转到对应回源页且能定位（至少任务粒度）；
- [ ] 勾选完成仍能正确写入对应存储。

### 6.2 A-2 任务生命周期

**用户故事**：作为成员，我想把任务标记为"进行中/已完成/已取消"并设置截止时间，这样我能管理进行中的事项而不丢失历史。

- `tasks` 表/契约新增字段：`status`（`todo` / `in_progress` / `done` / `cancelled`，默认 `todo`）、`dueAt`（ISO 时间，可空）。
- API：`GET /api/tasks?status=` 支持筛选；`PATCH /api/tasks/:id` 支持 `status`、`dueAt`。
- UI：`/todos` 列表增加状态切换（点击状态标签循环切换或下拉），截止时间使用现有 `DateTimePicker`；新建/编辑表单增加"截止时间"字段。
- 兼容：现有"完成"按钮映射为 `status=done`；`DELETE /api/tasks/completed` 语义不变。
- 数据契约变更需同步：`shared/` 契约、fallback 数据、对应测试（tests 中 tasks 相关）。

**验收标准**：
- [ ] 创建任务可设截止时间；互操作不破坏现有完成/删除；
- [ ] 状态筛选生效；`npm test` 通过；
- [ ] 迁移现有 SQLite 数据不丢失（老任务默认 `todo`）。

### 6.3 A-3 逾期任务治理

**用户故事**：作为成员，我想看到并处理逾期任务，这样我不会让该做的事无声沉底。

- Today 与 `/todos` 顶部展示"逾期分组"；逾期 > 3 天用警示色。
- 操作：`顺延`（把 dueAt 改为今天/明天，保留状态）、`完成`、`取消`。
- 提供批量"清空逾期提醒"（仅关闭提醒态，不改状态）。

**验收标准**：
- [ ] 逾期分组在有逾期任务时置顶显示；
- [ ] 顺延操作会更新 dueAt 并退出逾期分组。

### 6.4 B-1 日报送达与已读反馈

**用户故事**：作为成员，我想知道日报是否送达并被主管看到，这样我对提交这件事有确定感。

- Team Server：`daily_reports` 增加 `read_at DATETIME NULL`；
  - `PUT /api/team/daily-reports/me/:date` 写入时不改 read_at；
  - 主管读取该日报的接口（`GET /api/team/reports` 或新增明细接口）时，若 `read_at IS NULL` 且查看者为该用户直管，则更新 read_at 并记审计。
- 前端：
  - 日报页提交成功态文案：`已送达 {reportRecipient} · {时间}`；
  - 若 read_at 非空显示"已读"标记。
- 合规提示：此"已读"为系统状态，仅展示送达/已读，不推第三方通知。

**验收标准**：
- [ ] 提交后显示送达对象；直管查看后提交人可见"已读"；
- [ ] 审计日志记录 read 事件；
- [ ] 老数据无 read_at 时显示"已送达"而非"已读"。

### 6.5 B-2 未提交提醒

**用户故事**：作为成员，我想在漏交日报时有个提醒，这样我不会连续漏交。

- 日报页：当前日期晚于所选日报日期且未提交时，显示内联提醒条"X 号日报未提交，点击补充"。
- 首屏 Today 页：若"昨日无已提交日报"且当前为工作日上午，显示横幅"昨日日报未提交"，链接到 `/daily-report`。
- Electron 端：本地草稿存在且未同步时保持不变（现状），不新增系统级通知（避免打扰）。

**验收标准**：
- [ ] 漏交场景下日报页与 Today 页分别出现对应提醒；
- [ ] 提交后提醒消失。

### 6.6 B-3 主管日报视图

**用户故事**：作为主管，我想按"我的下属"查看实时日报并在一个页面处理，这样我不用在列表里翻找。

- 复用 `/api/team/reports` + `/api/team/members` 数据，前端新增"我的下属"筛选维度（依据 `manager_user_id` / `users.manager` 关系）。
- 新增**单日速览模式**：按日聚合展示下属成员的"阻塞 + 行动 + 决策标记"，一屏扫完。
- 管理员原有全局视图（按部门/日期）保留。
- 前端路由建议：`/team-reports` 增加 Tab（`全局` / `我的下属`）；权限沿用现有角色守卫。

**验收标准**：
- [ ] 主管能看到其下属未提交/已提交列表与单日速览；
- [ ] 普通成员被重定向的现状不被破坏。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 隐私与安全 | 已读/催办等新字段不得包含邮件正文、凭据；一切保持 loopback-only；变更后必须过 `npm run privacy:scan` |
| 兼容性 | 原有 API 语义向前兼容；新增字段默认值不得破坏旧前端；Web/Electron/托管三形态行为一致（fallback 规则不变） |
| 性能 | Today 与日报页聚合请求保持并发；新增接口应复用现有索引与查询，不引入全表扫描以上的量级 |
| 测试 | 数据契约/API 边界/状态流转必须补回归测试；提交前运行对应专项测试 + `npm test` |
| 可维护性 | 遵循 KISS：单一职责、函数 ≤20 行、中文注释；不进行大规模重构 |

## 8. 里程碑规划（解决"从哪入手"）

> 原则：每个里程碑独立可交付、可验证、不破坏现状。

| 里程碑 | 内容 | 交付验证 |
| --- | --- | --- |
| **M1 行动闭环**（约 1 周） | A-1、A-2、A-3（Today 卡片升级 + 任务状态/截止/逾期治理） | Today 页可完成"识别 → 处理 → 完成"全流程 |
| **M2 个人日报确定性**（约 1 周） | B-1、B-2 送达/已读/漏交提醒 | 成员对"日报交没交、交到哪"有确定感 |
| **M3 主管效率**（约 2 周） | B-3 主管视图 + B-5 决策回流 + B-1 已读取读联动 | 主管 5 分钟内完成全组日报扫描与决策 |
| **M4 团队节奏**（约 2 周） | B-4 催办、B-6 提交率看板、C-1 首屏引导 | 团队形成"日报-催办-复盘"节奏 |
| **M5 复盘打通**（储备） | B-7 团队周报下发、B-8 表扬、A-4~A-7 增强 | 个人与团队周报视角一致 |

首推路径：**M1 → M2 → M3**（先让个人闭环确定，再放大到主管层）。

## 9. 成功指标（建议观测）

- 日报连续提交率：连续 5 个工作日提交 ≥ 4 天（个人）；团队提交率 ≥ 80%（管理员）。
- Today 页日均行动完成数 > 0（有完成行为发生）的用户占比。
- 从"打开 Today"到"提交日报"的主线路径中，页面跳转次数 ≤ 3。
- 主管单日处理下属日报耗时 ≤ 5 分钟（主观评估）。
